OTP 세션 설계

pytest 테스트 파일이 하나도 없는 단계에서 시작한다. 카카오톡으로 오는 1회용 인증번호는 사람이 직접 쳐야 하는데, 테스트는 100개를 돌려야 한다 — 이 둘을 같이 만족시키는 구조를 처음부터 하나씩 쌓아 올린다.

2026-08-28 대상: 파이참 + Playwright 설치까지 끝난 단계 필요 설치: pytest, pytest-playwright, python-dotenv
시작하기 전 page 는 어디서 오나 로그인 fixture conftest.py session scope OTP 를 얹으면 OTP 설계 전체 그림 스스로 점검 부록
00 · 시작하기 전

지금 있는 것과 만들 것

Codegen 실습에서 만든 건 스크립트다. sync_playwright() as p: 블록 하나가 처음부터 끝까지 브라우저를 직접 열고 닫는다. 이 문서에서 만들 건 pytest 테스트다 — 파일 이름과 함수 이름에 규칙이 있고, "준비물"을 fixture 라는 것이 대신 챙겨준다. 완전히 다른 종류의 코드는 아니고, 같은 Playwright 위에 pytest 라는 도구를 하나 더 얹는 것이다.

설치

아래 셋이 필요하다. 이미 Playwright 는 깔려 있을 테니 나머지 둘만 추가한다.

pip install pytest pytest-playwright python-dotenv
playwright install chromium

pytest-playwright 가 이 문서의 핵심이다. 이걸 깔면 browser, page 같은 걸 우리가 직접 만들지 않아도 테스트 함수가 바로 받아 쓸 수 있게 된다 — 그 이유를 바로 다음 섹션에서 본다.

01 · 첫 번째 발견

page 는 어디서 오나

먼저 지금까지 짜던 방식과 나란히 놓고 본다.

지금까지 — 스크립트
from playwright.sync_api import sync_playwright

with sync_playwright() as p:
    browser = p.chromium.launch(headless=False)
    page = browser.new_page()
    page.goto("https://example.com")
    print(page.title())
    browser.close()

이제 pytest 버전이다. 파일 이름은 test_로 시작, 함수 이름도 test_로 시작해야 pytest 가 찾아서 실행한다.

test_example.py
def test_example_title(page):
    page.goto("https://example.com")
    assert "Example" in page.title()
개념 — fixture

함수 이름을 잘 보면 page 라는 인자를 받는다. 우리는 page 를 만든 적이 없는데 함수 안에서 바로 쓴다 — 이미 브라우저가 열리고 새 페이지가 만들어진 채로 넘어온 것이다. 이렇게 테스트가 실행되기 전에 준비물을 만들어서 건네주는 것을 fixture 라고 부른다. page 는 우리가 만든 게 아니라 pytest-playwright 가 미리 만들어 둔 fixture다. browser· context 도 같은 방식으로 쓸 수 있다.

실행은 이렇게 한다.

pytest test_example.py -s
02 · 직접 만들기

로그인 fixture 만들기

page 는 그냥 빈 페이지다. 우리 서비스는 로그인부터 해야 쓸모가 있다. 테스트마다 로그인 코드를 반복해서 적으면, 로그인 화면이 바뀔 때마다 모든 테스트 파일을 다 고쳐야 한다 — 그래서 우리가 직접 fixture 를 하나 만든다.

test_dashboard.py
import pytest

@pytest.fixture
def logged_in_page(page):
    page.goto("https://your-service.example")
    page.get_by_placeholder("아이디").fill("내_아이디")
    page.get_by_placeholder("비밀번호").fill("내_비밀번호")
    page.get_by_role("button", name="로그인").click()
    return page


def test_dashboard_visible(logged_in_page):
    assert logged_in_page.get_by_text("대시보드").is_visible()
눈여겨볼 것

logged_in_page 는 우리가 지은 이름이다. page 를 받아서 로그인시킨 다음 그대로 돌려준다. 테스트 함수는 page 대신 logged_in_page 를 인자로 받기만 하면 이미 로그인된 페이지를 받는다 — 로그인 코드를 한 글자도 다시 안 써도 된다.

비밀번호를 코드에 그대로 적지 않는다

위 예시는 설명을 위해 값을 그대로 썼다. 실제로는 .env 파일에 넣고 코드에서 읽는다.

# .env (커밋하지 않는다 — .gitignore 에 추가)
LOGIN_ID=실제아이디
LOGIN_PW=실제비밀번호
import os
from dotenv import load_dotenv

load_dotenv()
LOGIN_ID = os.getenv("LOGIN_ID")
LOGIN_PW = os.getenv("LOGIN_PW")
03 · 공유하기

여러 파일이 같이 쓰게 — conftest.py

테스트 파일이 test_dashboard.py 하나뿐이면 문제없다. 그런데 test_settings.py 도 로그인이 필요하다면? fixture 를 복사해서 붙여넣으면, 로그인 방식이 바뀔 때 두 파일을 다 고쳐야 한다.

해결은 간단하다. fixture 를 conftest.py 라는 이름의 파일로 옮긴다. pytest 는 이 이름을 특별하게 취급해서, 같은 폴더(와 하위 폴더)의 모든 test_*.py 가 import 없이 그 fixture 를 바로 쓸 수 있게 해준다.

project/
├── conftest.py ← logged_in_page 를 여기로 옮긴다
├── test_dashboard.py # import 없이 그대로 씀
└── test_settings.py # 여기서도 그대로 씀
왜 import 가 필요 없나

conftest.py 는 코드가 아니라 pytest 에게 주는 "이 폴더의 공용 준비물 목록"이다. 이름 자체가 규칙이라, pytest 가 테스트를 실행하기 전에 알아서 읽는다. 그래서 파일명을 다르게 지으면 안 된다.

04 · 속도

매번 로그인은 느리다 — session scope

지금 만든 logged_in_page 는 테스트 함수마다 새로 실행된다(fixture 의 기본값). 테스트가 100개면 로그인도 100번 한다 — 느리고, OTP 라면 사람이 100번 인증번호를 쳐야 한다.

그럼 이렇게 바꾸면 되지 않을까? 

@pytest.fixture(scope="session")  # 전체 실행에서 딱 한 번
def logged_in_page(page):
    ...
ScopeMismatch: You tried to access the function-scoped fixture "page" with a session-scoped request object.
왜 에러가 나나

page 는 테스트마다 새로 만들어지는 fixture 다(함수 스코프). 그런데 우리 fixture 는 "전체에서 한 번" (세션 스코프)이라고 선언해놓고 그 안에서 매번-새로-만들어지는 page 를 받으려 했다 — 오래 사는 것이 짧게 사는 것을 품을 수 없다는 게 pytest 의 규칙이다.

해결 — 두 단계로 나눈다

세션 스코프 fixture 는 "페이지"가 아니라 "로그인된 상태"를 저장만 한다(storage_state). 테스트마다 쓰는 fixture 는 그 저장된 상태로 새 페이지만 새로 연다 — 로그인은 다시 안 한다.

@pytest.fixture(scope="session")
def auth_state(browser):
    # browser 는 pytest-playwright 가 세션 스코프로 이미 만들어 둔 것 —
    # 세션 fixture 끼리라 여기서는 스코프가 안 부딪힌다
    context = browser.new_context()
    page = context.new_page()
    page.goto("https://your-service.example")
    page.get_by_placeholder("아이디").fill(LOGIN_ID)
    page.get_by_placeholder("비밀번호").fill(LOGIN_PW)
    page.get_by_role("button", name="로그인").click()
    page.wait_for_timeout(2000)

    state_path = "auth_state.json"
    context.storage_state(path=state_path)  # 페이지가 아니라 '인증 정보'를 저장
    context.close()
    return state_path


@pytest.fixture  # 기본값 = 테스트마다
def logged_in_page(browser, auth_state):
    context = browser.new_context(storage_state=auth_state)  # 로그인 다시 안 함
    page = context.new_page()
    yield page
    context.close()
참고

"auth_state.json" 을 프로젝트 폴더에 그대로 쓰면 실행할 때마다 덮어써지고, 실수로 커밋될 수도 있다. 실전에서는 pytest 가 주는 tmp_path_factory fixture 로 임시 폴더에 저장한다 — 실행이 끝나면 자동으로 정리된다. 지금은 개념만 잡고 넘어가도 된다.

체크포인트 — 지금까지 만든 것

여기까지 오면 완전히 동작하는 구조 하나가 생긴다. OTP 없는 서비스면 이걸로 끝이다. 파일 두 개, 명령 하나.

여기까지 손으로 따라 만들어 보고, 실제로 로그인이 되는 것까지 확인한 다음 다음 섹션으로 넘어가는 걸 권한다. OTP 는 이 구조 위에 얹는 것이지, 다시 짜는 게 아니다.

05 · 문제 정의

여기에 OTP 를 얹으면

위 auth_state 는 "코드가 아이디·비밀번호를 다 알고 있으니 혼자 로그인까지 끝낼 수 있다"는 전제로 짜여 있다. OTP 가 끼면 이 전제가 깨진다 — 코드는 그 값을 모른다. 로그인 버튼을 눌러야 카카오톡으로 번호가 발송되고, 그 번호는 실행 시점에만 존재해서 .env 에 미리 넣어둘 수 없다. 자동화 흐름 한가운데 "사람이 화면을 보고 직접 입력해야 하는 순간"이 반드시 끼어든다.

안다 — .env

실행 전부터

있다

다행히 구조는 그대로 쓴다. auth_state 가 세션당 한 번만 실행되니, 사람이 개입하는 순간도 세션당 한 번이면 된다. 그 한 번을 어떻게 다룰지가 아래 다섯 가지다.

06 · 설계

OTP 설계 다섯 가지

auth_state 안의 _login 부분을 이 순서로 다듬는다.

01 / 05

사람이 칠 시간을 어떻게 벌 것인가

그냥 짜면 — 로그인 버튼을 누르고 바로 "성공?" 을 확인한다.

문제

카카오톡으로 오는 데 몇 초에서 몇십 초 걸린다. 너무 일찍 확인하면 사람이 치기도 전에 타임아웃 난다.

이렇게 만든다

인증번호 입력창이 나타나는지부터 먼저 기다린다. 나타나면 그때 대기 시간을 사람이 실제로 칠 수 있을 만큼 크게 늘린다.

OTP_WAIT_SEC = int(os.getenv("OTP_WAIT_SEC", "180"))
...
wait_ms = 15000
try:
    page.get_by_placeholder("인증번호").first.wait_for(state="visible", timeout=4000)
    print(f"[로그인] 인증번호 입력이 필요합니다. 최대 {OTP_WAIT_SEC}초 기다립니다.")
    wait_ms = OTP_WAIT_SEC * 1000
except Exception:
    pass  # 이 계정은 항상 OTP 이므로 사실 여기로 올 일이 없다

page.wait_for_function(IS_AUTHED_JS, timeout=wait_ms)  # 다음 카드에서 정의
02 / 05

사람이 치려면 창이 보여야 한다

그냥 짜면 — pytest --headed 로 실행해서 모든 테스트가 창을 띄우게 한다.

문제

headless 는 브라우저 단위 설정이다. --headed 를 주면 로그인 창 하나 보자고 나머지 99개 테스트까지 전부 창을 열고 닫는다.

이렇게 만든다

로그인 전용 브라우저를 하나 더 띄운다. 거기서 OTP 까지 받고 곧바로 닫는다. 나머지 테스트는 원래 있던 headless 브라우저를 그대로 쓴다.

LOGIN_HEADED = os.getenv("LOGIN_HEADED", "") not in ("", "0", "false")

@pytest.fixture(scope="session")
def auth_state(browser, browser_type):
    login_browser = browser_type.launch(headless=False) if LOGIN_HEADED else None
    context = (login_browser or browser).new_context(...)
    ...
    finally:
        context.close()
        if login_browser:
            login_browser.close()   # OTP 입력이 끝났으므로 닫는다
참고

매번 OTP 계정만 쓸 거라면 환경변수로 켜고 끄는 대신 처음부터 headless=False 를 고정값으로 써도 된다.

03 / 05

창은 떴는데 화면에 안 보인다

그냥 짜면 — 다른 테스트에서 쓰던 뷰포트 크기를 로그인 컨텍스트에도 그대로 재사용한다.

문제

큰 표를 검증하려고 세로로 아주 길게(예: 1920×2600) 잡아둔 뷰포트를 그대로 쓰면, 세로 가운데 정렬된 로그인 폼이 화면 한참 아래로 밀려서 안 보인다. 창은 떴는데 사람이 클릭할 수가 없다.

이렇게 만든다

로그인 전용 컨텍스트는 실제로 화면에 들어가는 크기 로 따로 잡는다.

context = (login_browser or browser).new_context(
    viewport={"width": 1280, "height": 900})
참고

본인 화면의 로그인 폼이 어디에 그려지는지 먼저 눈으로 확인하고, 그 폼이 다 들어오는 가장 작은 크기로 잡으면 된다. 정답 크기는 서비스마다 다르다.

04 / 05

로그인이 끝났다는 걸 어떻게 판정하나

그냥 짜면 — URL 이 로그인 화면이 아니면 성공, 또는 인증 쿠키가 있으면 성공으로 본다.

문제

서비스에 따라 로그인 화면이 /login 이 아니라 루트(/)일 수 있다 — 그러면 로그인을 안 해도 URL 조건이 항상 참이다. 또 어떤 앱은 페이지를 열자마자 값이 빈 쿠키를 미리 깔아둔다 — 그러면 "쿠키가 있는가" 도 로그인 전부터 항상 참이다. 둘 다 실제로 이런 식으로 걸린다.

이렇게 만든다

특정 인증 쿠키의 값 길이를 본다. "있다/없다"가 아니라 "채워졌다/비었다" 로 판정 기준을 바꾼다.

AUTH_COOKIE = "session-token"  # 본인 서비스의 실제 쿠키 이름으로
IS_AUTHED_JS = (
    "() => (document.cookie.match(/(?:^|;\\s*)%s=([^;]*)/) || [, ''])[1].length > 0"
    % AUTH_COOKIE
)
이 쿠키 이름을 어떻게 찾나

개발자도구 → Application 탭 → Cookies 에서, 로그인 전과 후를 나란히 비교한다. 로그인 전엔 비어 있다가 후에만 값이 채워지는 쿠키를 찾으면 그게 정답이다.

05 / 05

OTP 없는 계정도 같이 돌려야 한다면

계정을 두 종류(OTP 없음 / 있음) 다 지원해야 하는 경우도 있다. 하드코딩하면 한쪽만 된다.

이렇게 만든다

환경변수로 두 종류의 OTP를 구분한다 — 코드가 값을 미리 아는 "고정 OTP" 계정과, 사람이 직접 쳐야 하는 "1회용 OTP" 계정.

FIXED_OTP = os.getenv("LOGIN_OTP", "")
...
if FIXED_OTP:  # 코드가 값을 미리 아는 경우
    try:

참고 — 지금 당장 필요할까

계정이 "코드가 값을 모르는" 경우 하나뿐이라면 이 분기는 필요 없다. 있으면 유연하지만, 없어도 지금은 문제없다 — 나중에 다른 종류의 계정을 쓰게 될 때 추가해도 늦지 않다. 안 아픈 곳을 미리 대비해 코드를 복잡하게 만들 필요는 없다.

완성된 예시 — conftest.py 전체

이 문서에서 단계별로 만든 것을 전부 이어붙인 것이다. 그대로 복사해서 쓰라는 게 아니라 — 본인 서비스의 placeholder 문구, 버튼 이름, 인증 쿠키 이름은 전부 다를 것이다. 구조만 그대로 가져오고, 이름은 본인 화면에 맞게 바꿔서 짠다.

전체 코드 보기 
import os
import pytest
from dotenv import load_dotenv

load_dotenv()

BASE_URL = os.getenv("BASE_URL", "").rstrip("/")
LOGIN_ID = os.getenv("LOGIN_ID")
LOGIN_PW = os.getenv("LOGIN_PW")
FIXED_OTP = os.getenv("LOGIN_OTP", "")            # 코드가 값을 미리 아는 계정용 (선택)
OTP_WAIT_SEC = int(os.getenv("OTP_WAIT_SEC", "180"))
LOGIN_HEADED = os.getenv("LOGIN_HEADED", "") not in ("", "0", "false")

# 본인 서비스에서 로그인 후에만 값이 채워지는 쿠키 이름으로 바꾼다
# (개발자도구 Application 탭에서 로그인 전/후 비교로 찾는다)
AUTH_COOKIE = "session-token"
IS_AUTHED_JS = (
    "() => (document.cookie.match(/(?:^|;\\s*)%s=([^;]*)/) || [, ''])[1].length > 0"
    % AUTH_COOKIE
)


def _login(page):
    page.goto(BASE_URL)
    page.get_by_placeholder("아이디").fill(LOGIN_ID)
    page.get_by_placeholder("비밀번호").fill(LOGIN_PW)
    page.get_by_role("button", name="로그인").click()

    if FIXED_OTP:
        try:
            page.get_by_placeholder("인증번호").fill(FIXED_OTP, timeout=3000)
            page.get_by_role("button", name="확인").first.click(timeout=3000)
        except Exception:
            pass

    wait_ms = 15000
    try:
        page.get_by_placeholder("인증번호").first.wait_for(state="visible", timeout=4000)
        print(f"\n[로그인] 인증번호 입력이 필요합니다. 최대 {OTP_WAIT_SEC}초 기다립니다.")
        wait_ms = OTP_WAIT_SEC * 1000
    except Exception:
        pass  # OTP 없는 계정 — 바로 판정으로 간다

    page.wait_for_function(IS_AUTHED_JS, timeout=wait_ms)


@pytest.fixture(scope="session")
def auth_state(browser, browser_type, tmp_path_factory):
    login_browser = browser_type.launch(headless=False) if LOGIN_HEADED else None
    context = (login_browser or browser).new_context(
        viewport={"width": 1280, "height": 900})
    page = context.new_page()
    try:
        _login(page)
        state_path = str(tmp_path_factory.mktemp("auth") / "state.json")
        context.storage_state(path=state_path)
    finally:
        context.close()
        if login_browser:
            login_browser.close()
    return state_path


@pytest.fixture
def logged_in_page(browser, auth_state):
    context = browser.new_context(storage_state=auth_state)
    page = context.new_page()
    yield page
    context.close()
다음에 볼 것 — 본인 서비스 로그인 화면을 개발자도구로 뜯어보기. Application 탭에서 로그인 전/후 쿠키를 나란히 비교해 어떤 쿠키가 값으로 채워지는지 먼저 찾는다. 그게 4번 결정의 시작점이다.

이 문서의 코드는 전부 이 문서 안에서 한 단계씩 쌓아 만든 것이다. 처음부터 완성본을 옮기지 말고, 위에서부터 순서대로 직접 쳐 보면서 단계마다 실행해 보는 걸 권한다.
