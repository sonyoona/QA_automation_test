이 문서는 allure 를 처음 쓰는 사람을 위한 것이다. 특정 프로젝트 규칙이 아니라 allure 자체를 다룬다. 자기 코드에 그대로 적용할 수 있다.

1.한 줄 요약 — allure 는 리포트 도구다

테스트가 어떻게 도는지는 하나도 안 바꾼다. 데코레이터를 전부 떼어내도 테스트는 똑같이 통과하고 똑같이 실패한다.

바뀌는 것은 결과를 사람이 읽을 수 있느냐뿐이다.

allure 없이   test_login_with_invalid_password[chromium]  FAILED
allure 쓰면   로그인 — 비밀번호가 틀리면 오류 문구가 뜬다   FAILED
              (인증 > 로그인 > 실패 케이스)

그래서 처음 보면 "이걸 왜 붙이지?" 싶다. 붙이는 이유는 둘이다.

  1. 결과를 읽기 위해 — 테스트가 100개를 넘어가면 함수명만으로는 뭐가 깨졌는지 모른다
  2. 테스트와 TC 문서를 잇기 위해 — 리포트의 TC-001 을 들고 TC 문서를 찾아갈 수 있다

2.설치하고 돌려보기

pip install allure-pytest
# ① 실행하면서 결과를 폴더에 쌓는다
pytest --alluredir=allure-results

# ② 리포트로 만들어 연다  (allure CLI 는 Java 가 필요하다)
allure serve allure-results

Java 가 없으면 공식 CLI 는 못 쓴다. 그때는 allure-results 폴더에 쌓인 *-result.json 을 직접 읽어 HTML 로 만드는 스크립트를 쓰면 된다 — 결과 파일 자체는 그냥 JSON 이라 어렵지 않다.

매번 옵션을 치기 싫으면 pytest.ini 에 넣어 둔다.

[pytest]
addopts = --alluredir=allure-results --clean-alluredir

--clean-alluredir 은 실행할 때마다 이전 결과를 지운다. 리포트가 깔끔해지는 대신 여러 번 나눠 돌린 결과를 합칠 수 없다 — 합쳐야 하면 이 옵션을 뺀다.

3.데코레이터 — 이 다섯 개면 충분하다

import allure

@allure.epic("인증")                       # 가장 큰 묶음
@allure.feature("로그인")                  # 그 안의 화면·기능
@allure.story("실패 케이스")                # 더 잘게
@allure.title("비밀번호가 틀리면 오류 문구가 뜬다")   # 사람이 읽는 제목
@allure.testcase("TC-001")                # TC 문서 번호
def test_login_wrong_password(page):
    ...

리포트에서는 이렇게 접힌다.

인증                                  ← epic
└─ 로그인                             ← feature
   └─ 실패 케이스                      ← story
      ├─ 비밀번호가 틀리면 오류 문구가 뜬다   ← title
      └─ 아이디가 없으면 …
데코레이터담는 것없으면
@allure.epic가장 큰 묶음 (제품·메뉴)트리 맨 위가 빈다
@allure.feature화면·기능분류가 뭉친다
@allure.story더 잘게 나눈 단위분류가 뭉친다
@allure.title사람이 읽는 한 줄 제목함수명이 그대로 찍힌다 ← 제일 아프다
@allure.testcaseTC 문서 번호리포트에서 문서를 못 찾아간다

셋(epic·feature·story)을 다 쓸 필요는 없다. 테스트가 적으면 feature 하나로도 충분하다. 나중에 늘어나면 그때 쪼갠다.

파일 전체가 같은 값이면 한 번만 쓴다

# 파일 맨 위 — 이 파일의 모든 테스트에 적용된다
pytestmark = [allure.epic("인증"), allure.feature("로그인")]

단, 한 파일에 여러 화면이 섞여 있으면 쓰면 안 된다. 전부 같은 값이 되어버린다.

4.allure.step — 실패했을 때 어디서 깨졌는지 보인다

def test_login_wrong_password(page):
    with allure.step("로그인 화면 열기"):
        page.goto("/login")

    with allure.step("틀린 비밀번호로 로그인 시도"):
        page.fill("#id", "tester")
        page.fill("#pw", "wrong")
        page.click("button[type=submit]")

    with allure.step("오류 문구 확인"):
        expect(page.get_by_role("alert")).to_be_visible()

리포트에서 단계별로 접혀서 보이고, 실패한 단계에 표시가 붙는다. 로그를 뒤지지 않아도 어디서 멈췄는지 바로 안다.

모든 줄에 붙이지 마라. 단계가 3~5개로 나뉘는 테스트에만 쓴다. 한 줄짜리 테스트에 step 을 두르면 읽기만 나빠진다.

5.실패 근거를 리포트에 남기기

allure.attach(
    page.screenshot(), "실패 시점 화면",
    attachment_type=allure.attachment_type.PNG)

allure.attach(
    response_body, "API 응답",
    attachment_type=allure.attachment_type.JSON)

스크린샷·응답·로그를 리포트에 붙일 수 있다. 실패했을 때만 붙이는 것이 좋다 — 전부 붙이면 리포트가 무거워진다. conftest.py 의 훅으로 자동화하는 것이 흔한 방식이다.

6.흔한 실수 셋

① @allure.title 을 빠뜨린다

리포트에 함수명이 그대로 찍힌다.

나쁨   test_login_wrong_password[chromium]
좋음   비밀번호가 틀리면 오류 문구가 뜬다

테스트는 통과하는데 결과를 못 읽는 상태가 된다. 가장 자주 나오는 실수다.

② 파라미터가 붙은 테스트에 제목을 고정으로 쓴다

# 나쁨 — 5개가 리포트에 전부 같은 제목으로 찍힌다
@allure.title("상태 탭 필터")
@pytest.mark.parametrize("tab", ["대기", "완료", "취소"])

# 좋음 — {tab} 자리에 값이 들어가 갈라 보인다
@allure.title("[{tab}] 탭 — 그 상태 건만 나온다")

③ 제목을 여러 곳에 중복해서 쓴다

@allure.title 과 docstring 첫 줄에 같은 문장을 적으면, 나중에 한쪽만 고쳐져 서로 달라진다. 제목은 @allure.title 한 곳에만 둔다. docstring 에는 GIVEN/WHEN/THEN 같은 상세를 적는다.

7.어디까지 쓸지 — 순서 추천

한꺼번에 다 하지 말고 이 순서로 붙이면 된다.

순서무엇을왜
1@allure.title효과가 제일 크다. 리포트가 바로 읽힌다
2@allure.feature테스트가 20개 넘어가면 분류가 필요해진다
3allure.step실패 원인을 빨리 찾고 싶어질 때
4@allure.testcaseTC 문서가 따로 있을 때만
5epic / story화면이 여러 개로 늘어난 뒤에

1번만 해도 절반은 얻는다. 나머지는 아쉬워질 때 붙이면 된다.

8.기억할 것 하나

allure 는 테스트를 더 정확하게 만들어 주지 않는다. 검증이 허술한 테스트에 예쁜 제목을 붙이면, 허술한 테스트가 잘 정리되어 보일 뿐이다.

리포트가 초록불이라는 것과 검증이 제대로 됐다는 것은 다른 얘기다. 데코레이터를 붙이기 전에 "이 검증 대상이 망가지면 이 테스트가 빨간불이 되나?" 를 먼저 자문하는 편이 낫다.
