새 프로젝트 시작할 때 프론트 개발자에게 전달하는 문서입니다. 개발 전에 드리는 것이 핵심입니다 — 만들고 나서 요청하면 그때부터 레거시가 됩니다.

QA 자동화가 화면 요소를 찾는 방법은 셋뿐입니다.

방법안정성비고
data-testid안정이 문서가 요청하는 것
접근성 role/이름 (버튼 글자 등)보통문구가 바뀌면 깨집니다
CSS 클래스·DOM 위치불안정스타일 리팩터링 한 번에 전부 깨집니다

testid 가 없으면 자동화는 3번으로 내려갑니다. 그러면 화면은 멀쩡한데 테스트만 깨지는 일이 반복되고, QA 는 그걸 고치느라 시간을 씁니다.

1. 명명 규칙

{화면접두어}__{요소이름}                    fs-new__submit-button
{화면접두어}__{요소이름}--{식별자}          fs-table__row--10631
  • 접두어를 화면마다 하나씩 정해 주세요. QA 는 [data-testid^="fs-table__row--"] 처럼 접두어로 묶어 잡는 일이 많습니다.
  • 케밥케이스(-)로 쓰고, 구분은 __, 식별자는 -- 입니다.

2. 목록·표의 항목에는 식별자를 함께 넣어 주세요

<tr data-testid="order__row--10631">

표시 텍스트로는 행을 구분할 수 없는 경우가 있습니다. 실제로 겪은 일입니다 — 같은 날 같은 업체로 만든 건이 여러 개라 1페이지 마지막 행과 2페이지 첫 행의 텍스트가 글자까지 같았습니다. 페이지네이션 테스트 2건이 그것 때문에 깨졌습니다. PK 가 testid 에 있으면 이런 문제가 없습니다.

같은 이유로 날짜·이름 같은 값도 식별자로 좋습니다.

<button data-testid="datepicker__day--2026-08-01">1</button>

캘린더에 숫자만 있으면 이전 달 1일과 이번 달 1일을 구분할 수 없습니다.

3. 라벨이 아니라 값에 붙여 주세요

<!-- 이러면 QA 가 다시 형제 요소를 찾아 헤매게 됩니다 -->
<label data-testid="detail__cancel-actor-label">취소자</label>
<span>함경섭 (현재 로그인 계정)</span>

<!-- 이렇게 -->
<label>취소자</label>
<span data-testid="detail__cancel-actor">함경섭 (현재 로그인 계정)</span>

라벨에만 있으면 이런 사고가 납니다 — 라벨은 화면에 항상 박혀 있는 안내 문구라 값이 비어도 테스트가 통과합니다. 실제로 취소자 라벨만 확인하다가 값이 비어도 초록불이 뜨는 테스트가 있었습니다.

4. 동적으로 열리는 것은 반드시 필요합니다

팝오버·드롭다운·모달·툴팁처럼 body 끝에 붙어서 열리는 것들입니다. 이런 건 testid 가 없으면 CSS 클래스말고는 잡을 방법이 없습니다.

# testid 가 없어서 이렇게 잡고 있는 실제 코드
page.get_by_text("오늘").locator("xpath=ancestor::div[contains(@class,'w-[280px]')]")

Tailwind 클래스 하나 바뀌면 그날 깨집니다.

대상예
컨테이너datepicker__root · dialog__confirm
그 안의 조작datepicker__prev-month · datepicker__today
목록 항목select__option--{value}

5. 아이콘만 있는 버튼은 특히 필요합니다

글자가 없으면 접근성 이름도 없어서 get_by_role("button", name=...) 이 안 통합니다. 이전/다음 화살표, ✕ 닫기, 편집 연필 같은 것들입니다.

<button data-testid="chip__remove--IMS모빌리티"><XIcon /></button>

저희가 맡은 화면 중에도 캘린더 이전/다음 달 버튼을 DOM 순서(0번, 1번)로 누르고 있는 곳이 있습니다. 버튼이 하나 늘어나면 그대로 깨집니다.

6. 표 셀은 testid 대신 컬럼 키가 서로 편합니다

<!-- 행 id 를 조합해야 해서 개발 쪽이 번거롭습니다 -->
<td data-testid="table__cell--10631--status">완료</td>

<!-- 컬럼 이름만 있으면 됩니다. QA 도 컬럼 순서와 무관해집니다 -->
<td data-col="status">완료</td>

없어도 헤더 텍스트로 찾는 우회책이 있어서 우선순위는 낮습니다. 다만 컬럼이 중간에 추가되면 QA 코드를 손봐야 합니다 (다른 화면에서 실제로 겪었습니다 — 컬럼 하나가 추가되어 14 → 15컬럼이 됐습니다).

7. 상태는 표준 속성으로 표현해 주세요

<!-- 좋음 — QA 가 그대로 읽습니다 -->
<button disabled>저장</button>
<div role="option" aria-disabled="true">…</div>
<div role="tab" aria-selected="true">전체</div>

<!-- 나쁨 — 클래스로만 표현하면 QA 가 클래스명을 외워야 합니다 -->
<button class="btn-disabled-gray">저장</button>

disabled · aria-disabled · aria-selected · aria-expanded 만 제대로 붙어 있으면 그 상태들은 testid 없이도 안전하게 검증됩니다.

8. 안 붙여도 되는 것

전부 붙일 필요는 없습니다. 이런 건 그냥 둬도 됩니다.

  • 글자가 안정적인 버튼 ([조회], [저장]) — role+name 으로 충분
  • 정적인 안내 문구·제목
  • 레이아웃용 div

요청드리는 순서

"이번에 작업하시는 범위에 들어오는 화면" 기준으로 봐주시면 됩니다. 새 페이지를 매번 만드는 게 아니라 기존 화면을 개선하거나, 새 페이지가 레거시 화면을 참조하는 경우가 많다고 들었습니다.

대상부탁드리는 것
새로 만드는 페이지1~5 번
그 작업에서 함께 손보는 레거시 화면1~5 번 (같은 기준)
작업 범위 밖의 레거시지금은 안 하셔도 됩니다

같은 기준으로 부탁드리는 이유는, 이미 그 파일을 열고 계실 때가 부담이 가장 적을 것 같아서입니다. 나중에 따로 하면 일이 이렇게 늘어납니다.

작업하면서 같이나중에 따로
코드 파악지금 보고 있으니 불필요다시 열어 구조 파악
영향 확인불필요공유 컴포넌트면 다른 화면까지 확인
QA 쪽바로 testid 로 작성그 사이 짜둔 우회 코드도 다시 수정

저희도 그 사이에 짜둔 우회 코드를 다시 고쳐야 해서, 결국 양쪽이 두 번 일하게 됩니다.

저희가 아는 범위에서는 동작에 영향이 없는 작업입니다. data-testid 는 조건문·상태·스타일에 관여하지 않는 속성이라, 보통 레거시를 만지기 꺼려지는 이유("뭐가 깨질지 몰라서")와는 성격이 다릅니다. 물론 공유 컴포넌트라 걸리는 부분이 있으시면 말씀해 주세요 — 저희가 다른 방법을 찾겠습니다.

// 늘어나는 건 이 한 줄뿐입니다
<div data-testid="datepicker__root" className="...">

우선순위 — 시간이 빠듯하시면 이 순서로 봐주세요.

  1. 4번 (팝오버·드롭다운·모달) — 여기만 CSS 클래스에 의존하게 되어, 스타일 한 번 정리하시면 테스트가 한꺼번에 깨집니다
  2. 5번 (아이콘만 있는 버튼) — 접근성 이름이 없어 잡을 방법이 마땅치 않습니다
  3. 1·2·3번
  4. 6·7번 — 저희 우회책이 튼튼해서 급하지 않습니다

작업 범위 밖의 레거시는 저희가 정말 막힌 곳만 따로 목록으로 정리해 드리겠습니다. 그때 여유 보시고 판단해 주시면 됩니다.

참고 — 이렇게 해주시면 QA 코드가 이렇게 됩니다

# testid 있을 때 — 읽으면 뜻이 보입니다
page.get_by_test_id("fs-new__submit-button").click()
expect(page.get_by_test_id("fs-detail__cancel-actor")).to_have_text("함경섭")

# 없을 때 — 이런 걸 짜야 하고, 화면이 조금만 바뀌어도 깨집니다
page.get_by_text("오늘").locator("xpath=ancestor::div[contains(@class,'w-[280px]')]")
dlg.locator("label", has_text=re.compile(r"^서비스유형$")).locator(
    "xpath=following-sibling::div//input")
row.locator("td").nth(_col(page, "상태"))
