Playwright · 실습

Codegen 직접 해보기

클릭하면 코드가 나오는 도구입니다. 40분이면 끝나는 실습으로, 무엇을 할 수 있고 무엇을 못 하는지 직접 겪어보는 게 목적입니다.

먼저 알아두실 것

codegen 이 뱉는 코드는 그대로 쓰는 게 아닙니다. 실습 5·8 에서 왜 그런지 직접 보시게 됩니다. 지금은 몰라도 되고, 순서대로 따라오시면 됩니다.

준비설치와 실행

이미 Playwright 를 설치하셨다면 두 번째 줄만 치시면 됩니다.

# 아직 설치 전이라면
pip install playwright
playwright install chromium

# codegen 실행 — 주소는 아무거나 (여기선 연습용 공개 사이트)
python -m playwright codegen https://playwright.dev/

창이 두 개 뜹니다.

창하는 일
브라우저여기서 직접 클릭·입력합니다
Playwright Inspector클릭할 때마다 코드가 쌓입니다
안 뜨면

playwright 명령을 못 찾는다고 나오면 python -m playwright codegen … 로 해보세요. 가상환경을 쓰신다면 활성화한 상태여야 합니다.

실습순서대로 여덟 가지

각 단계 끝의 확인할 것을 꼭 보고 넘어가세요. 거기가 핵심입니다.

1

아무거나 클릭해보기

브라우저에서 링크·버튼을 몇 개 눌러보세요. Inspector 창에 코드가 쌓입니다.

page.get_by_role("link", name="Docs").click()
page.get_by_role("button", name="Search").click()
확인할 것 — 클릭한 순서와 코드 순서가 같은가요? codegen 은 받아적기만 합니다. 스스로 판단하지 않습니다.
2

입력해보기 · 실수도 해보기

검색창에 글자를 넣었다가 일부러 지우고 다시 넣어보세요.

확인할 것 — 지운 것도 코드에 남아 있나요? 실수까지 전부 기록됩니다. 그래서 나온 코드는 항상 정리가 필요합니다.
3

Pick Locator 써보기 — 여기가 제일 유용합니다

먼저 Record 를 멈추세요. 그러면 툴바에 Pick locator 버튼이 나타납니다.

버튼을 누르고 브라우저에서 요소 위에 마우스를 올리면, 그 요소 아래에 셀렉터가 뜹니다. 클릭하면 버튼 옆 칸에 코드가 담깁니다.

page.get_by_role("link", name="Docs")
확인할 것 — 같은 버튼이라도 어디를 누르냐에 따라 다른 셀렉터가 나옵니다. 글자를 누를 때와 바깥 테두리를 누를 때를 비교해 보세요. 나중에 "왜 안 잡히지" 하는 원인이 대개 여기 있습니다.

아래쪽 Locator 탭에 셀렉터를 직접 쳐 넣으면 반대로도 됩니다 — 브라우저에서 해당 요소가 하이라이트됩니다. 다만 몇 개가 잡혔는지 숫자로는 안 알려줍니다 (그건 VS Code 확장에서 됩니다).

4

우리 서비스에서 해보기 — testid 가 보입니다

이제 실제 테스트 대상에서 해보세요. 로그인부터 직접 하시면 됩니다.

playwright codegen https://(우리 서비스 주소)

로그인하고, 메뉴를 눌러 목록 화면까지 들어가서 필터나 탭을 클릭해보세요.

확인할 것 — 어떤 곳은 get_by_role(...) 로, 어떤 곳은 get_by_test_id(...) 로 잡힐 겁니다. 왜 다를까요? 다음 장에 답이 있습니다.
5

검증(assert) 버튼 써보기

Record 오른쪽에 작은 아이콘 세 개가 있습니다. 마우스를 올리면 이름이 뜹니다.

순서가 중요합니다 — 아이콘을 먼저 누르고, 그 다음 브라우저에서 요소를 클릭합니다. 반대로 하면 그냥 클릭으로 기록됩니다.

1. Record 를 켠 상태에서
2. 검증 아이콘을 누르고
3. 브라우저에서 검증할 요소를 클릭
       ↓
4. Inspector 코드 창에 자동으로 한 줄이 추가된다
버튼만들어지는 것
assert visibility그 요소가 보이는가
assert text그 요소에 이 글자가 들어 있는가
assert value입력칸에 이 값이 들어 있는가

이렇게 나옵니다 — 직접 타이핑하는 게 아니라 Inspector 에 자동으로 생기는 것입니다.

expect(page.get_by_test_id("fs-page__root")).to_be_visible()
expect(page.get_by_role("tab", name="전체")).to_contain_text("전체")

다 만들었으면 복사 버튼으로 전체 코드를 가져와, PyCharm 에서 .py 파일로 저장하고 실행하면 됩니다(실습 8).

확인할 것 — 표의 모든 행이 조건에 맞는지는 만들 수 있나요? 못 만듭니다. 요소 하나씩만 됩니다. 그 차이가 다음 장의 핵심입니다.
6

로그인 한 번만 하기 — save-storage

매번 로그인하기 번거로우시죠. 로그인 상태를 파일로 저장해두면 됩니다.

# 1) 로그인하고 저장 (창을 닫으면 auth.json 이 만들어짐)
python -m playwright codegen (우리 주소) --save-storage auth.json

# 2) 다음부터는 로그인된 상태로 시작
python -m playwright codegen (우리 주소) --load-storage auth.json
확인할 것 — 두 번째 명령에서 로그인 화면이 안 뜨죠? 그래서 생성된 코드에 로그인 줄이 아예 안 들어갑니다. 실제 테스트 코드도 같은 원리(storage_state)로 로그인을 한 번만 합니다.
2FA(인증번호) 계정이면 특히 유용합니다

이 옵션이 없으면 녹화할 때마다 인증번호를 받아 쳐야 합니다. --save-storage 로 한 번만 통과해 두면, 저장된 쿠키에 이미 인증이 끝난 상태가 담겨 있어 다음부터는 로그인 화면 자체가 안 뜹니다.
다만 토큰에 수명이 있어 며칠 지나면 안 먹습니다 — 그때 --save-storage 로 한 번 더 받으면 됩니다.

auth.json 은 커밋하지 마세요

그 파일에는 로그인 토큰이 평문으로 들어 있습니다. 커밋되면 누구나 그 계정으로 로그인할 수 있습니다. .gitignore 에 넣고, 다 쓰면 지우세요.
(테스트 코드에서는 임시 폴더에 만들어 실행이 끝나면 자동으로 지워지게 합니다.)

7

모바일로 열어보기 — FMS (web-app)

렌터카 업체에서 차량 모니터링용으로 쓰는 화면입니다. 모바일에서 주로 보기 때문에, PC 브라우저로 열면 레이아웃이 달라집니다. 기기를 지정해 열어야 실제 사용자가 보는 화면이 나옵니다.

python -m playwright codegen --device "iPhone 13" https://dev-web-app-v2-1.carbom.co.kr/login
Windows PowerShell 에서는 등호(=)를 쓰지 마세요 
--device="iPhone 13"   # PowerShell 이 따옴표를 벗기고 공백에서 쪼갠다
--device "iPhone 13"   # 공백으로 띄우면 한 덩어리로 전달된다

playwright 를 못 찾는다고 나오면 앞에 python -m 을 붙이세요.

다른 옵션도 있습니다.

--device "Galaxy S9+"          # 안드로이드로
--viewport-size "1280,900"     # 크기만 지정
--color-scheme dark            # 다크모드로
확인할 것 — 같은 주소를 기기 지정 없이 한 번 더 열어보세요. 화면이 다르게 나오죠? 같은 서비스라도 보는 기기에 따라 검증할 것이 달라집니다.
기기 이름은 정해져 있습니다

아무 이름이나 되는 게 아니라 Playwright 가 아는 목록에서 골라야 합니다 (iPhone 13, Pixel 5, Galaxy S9+ 등). 틀리면 에러가 나니 그때 목록을 확인하시면 됩니다.

8

나온 코드를 실제로 돌려보기

Inspector 의 복사 버튼으로 코드를 가져와 파일로 저장하고 실행해보세요.

python 저장한파일.py
확인할 것 — 돌아가나요? 그리고 그 코드를 내일 다시 돌려도 통과할까요? 다음 장에 답이 있습니다.

해설실습에서 보신 것들

왜 어떤 건 testid 로, 어떤 건 role 로 잡히나

codegen 은 data-testid 가 있으면 그걸 먼저 씁니다. 없을 때만 역할(role)이나 글자로 잡습니다.

# testid 가 없는 화면 — 역할·글자로 잡힘
page.get_by_role("textbox", name="아이디")
page.get_by_role("link", name="현장 서비스")

# testid 가 있는 화면 — 자동으로 testid 를 씀
page.get_by_test_id("fs-filter__plate-input")
그래서 codegen 이 알려주는 것

"이 화면에 testid 가 붙어 있나 없나" 를 바로 알 수 있습니다. role 로 잡혔다면 testid 가 없는 겁니다 — 프론트에 요청할 대상이라는 뜻이고요.

검증은 되는데, 어디까지 되나

실습 5에서 보셨듯 codegen 도 검증을 만듭니다. 다만 요소 하나씩입니다.

# codegen 이 만들 수 있는 것 — 요소 하나
expect(page.get_by_test_id("fs-page__root")).to_be_visible()
expect(page.get_by_role("tab", name="전체")).to_contain_text("전체")

# 실제 TC 가 요구하는 것 — 결과 전체를 훑어야 한다
for r in 모든_행:
    상태 = r 의 상태 컬럼
    assert 상태 == "완료", f"[FAIL] '완료' 아닌 값이 섞임: {상태}"
차이가 왜 중요한가

"[완료] 탭을 누르면 완료 건만 나온다" 를 검증하려면 결과 행을 전부 봐야 합니다. 첫 행만 보면 나머지에 다른 상태가 섞여 있어도 통과합니다.

codegen 은 "이 요소가 이렇다" 까지 만들고, "모든 행이 이래야 한다" 는 못 만듭니다. 그건 무엇을 검증할지 사람이 정해야 나오는 것이라서요.

그리고 assert text 에는 함정이 하나 있습니다 
to_contain_text("완료")   # '포함' 이라 '배정완료'·'운영완료' 도 통과
to_have_text("완료")      # '정확히 같음'

codegen 은 포함(contains) 으로 만듭니다. 비슷한 이름이 있는 화면에서는 엉뚱한 것도 통과하니, 만들어진 코드를 한 번 보고 바꿔야 합니다.

주의그대로 쓰면 안 되는 이유

실습 5에서 받으신 코드를 다시 보시면 아래가 다 들어 있을 겁니다.

문제왜
검증이 얕다요소 하나씩만. "모든 행이 조건에 맞나" 는 못 만듦
비밀번호가 평문입력한 값이 코드에 그대로 박힘
실수도 기록됨잘못 클릭한 것, 지웠다 다시 친 것까지
로그인이 매번 복붙테스트가 100개면 로그인 코드도 100번 (--save-storage 로 녹화 때만 줄일 수 있음)
변하는 값이 박힘name="완료 217" — 건수가 바뀌면 깨짐
기다림이 없다사람이 클릭할 땐 화면이 이미 떠 있어서 필요 없었음

실제로 어떻게 깨지는지 — 탭 클릭 한 줄

화면의 상태 탭이 이렇게 생겼다고 해보겠습니다. 건수가 이름에 붙어 있습니다.

전체 576   대기 66   배정완료 93   완료 217
                                      ↑ 이 숫자까지 이름의 일부다

여기서 [완료] 탭을 클릭하면 codegen 은 이렇게 뽑습니다.

page.get_by_role("tab", name="완료 217").click()
문제 ① — 숫자가 박혔다

217은 오늘 건수입니다. 내일 218건이 되면 이 줄은 요소를 못 찾고 테스트가 깨집니다. 기능은 멀쩡한데 말이죠.

그럼 숫자만 빼면 될까요? 안 됩니다.

page.get_by_role("tab", name="완료")   # 숫자를 뺐다
문제 ② — 부분 일치라 다른 것도 잡힌다 
"완료" 로 찾으면
  ✓ 완료        ← 원하던 것
  ✓ 배정완료     ← 이것도 잡힌다
  ✓ 운영완료     ← 이것도

Playwright 의 name 은 포함으로 찾습니다. 둘 이상 잡히면 에러가 나거나 엉뚱한 탭을 누릅니다.

그래서 이렇게 씁니다

# codegen 이 뽑은 것
page.get_by_role("tab", name="전체")

# 실제 코드 — 정규식으로 '시작 지점' 을 고정한다
page.get_by_role("tab", name=re.compile("^설치기사"))
                                          ↑ ^ = 이 글자로 시작하는 것만
^ 하나가 하는 일 
name="완료"              →  완료 · 배정완료 · 운영완료   (3개)
name=re.compile("^완료")  →  완료                      (1개)

기다리는 시간도 다릅니다

# codegen
expect(page.get_by_test_id("fs-page__root")).to_be_visible()
                                            ↑ 기본 5초

# 실제 코드 — 이 화면은 데이터를 늦게 그린다
expect(page.get_by_test_id("fs-page__root")).to_be_visible(timeout=15000)

codegen 은 이걸 알 수가 없습니다. 사람이 클릭할 때는 화면이 이미 다 떠 있었으니까요.

특히 마지막 것

사람이 클릭할 때는 화면이 다 떠 있어서 기다릴 일이 없습니다. 그런데 코드로 돌리면 화면보다 코드가 빠릅니다. 데이터가 늦게 채워지는 화면이면 빈 값을 읽고 지나갑니다 — 그런데 테스트는 통과합니다. codegen 은 이걸 알려줄 수 없습니다.

정리언제 쓰면 되나

상황codegen
처음 보는 화면에 뭐가 있나 훑을 때좋음
이 요소를 코드로 어떻게 잡나 확인할 때좋음 (Locator 탭)
testid 가 붙어 있나 확인할 때좋음
Playwright 문법을 익힐 때좋음
테스트 코드를 만들 때쓰지 않음
한 문장으로

codegen 은 "화면에 뭐가 있나" 를 알려주는 도구이지, 테스트를 만들어주는 도구가 아닙니다. 셀렉터만 가져오고 나머지는 버리시면 됩니다.

한 걸음 더 — page.pause()

이미 작성한 테스트 중간에 같은 Inspector 를 띄우는 방법입니다.

def test_something(page):
    ...
    page.pause()        # 여기서 멈추고 Inspector 가 열린다
    ...
pytest -k something --headed -s

"셀렉터를 써놨는데 왜 안 먹지" 를 볼 때 이게 제일 빠릅니다. 로그인·화면 진입이 이미 끝난 상태에서 멈추니까요. 확인이 끝나면 그 줄은 지웁니다.
