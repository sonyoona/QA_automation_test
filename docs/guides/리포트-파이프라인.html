전체 흐름 네 가지 도구 bat / sh 실행 명령어
리포트 도구 네 가지

테스트 결과가 리포트가 되기까지

pytest 실행 한 번이 두 갈래의 산출물로 갈라진다 — 화면·로그까지 담는 공식 Allure 리포트와, 더블클릭으로 바로 열리는 QA 커스텀 리포트. 그 사이를 잇는 네 개 도구가 뭘 하는지, .bat와 .sh가 뭐가 다른지, PyCharm(PowerShell)에서 각각 어떻게 실행하는지를 정리했다.
01 · Pipeline

전체 흐름

postprocess_allure_results.py까지는 두 리포트가 같은 JSON을 공유한다. 그 다음부터 갈라진다 — 공식 리포트는 빌드와 서빙을 한 번씩 더 거치고, QA 리포트는 파일 하나로 끝난다.

02 · Tools

네 가지 도구

.py 둘은 위 다이어그램의 실제 처리 로직이고, .bat/.sh 둘은 그 로직을 순서대로 이어 부르는 실행 스크립트다.

PY postprocess_allure_results.py

원본 결과 JSON을 사람이 읽기 좋게 다듬는다.

  • fullName을 쪼개 testClass(파일명)·testMethod(함수명) 라벨을 새로 붙인다
  • feature 라벨에서 · xxx.py 부분을 잘라내 화면명만 남긴다
  • 실패·오류 메시지 맨 앞에 [실패 요약]/[실패 유형]/[실패 위치] 한글 요약 3줄을 붙인다
  • 같은 파일을 다시 돌려도 라벨·요약이 중복되지 않는다 (멱등)
allure-results/*.json →(수정)→ 같은 경로
PY generate_qa_report.py

서버 없이 더블클릭으로 열리는 자체완결 HTML을 만든다.

  • 모든 결과를 TC ID·화면(feature)·파일명·함수명·상태·소요시간으로 정리한다
  • 탭 네 개 — 요약 / 화면·기능별 / 상태별 / 전체 목록
  • 실패 건은 바로 아래 줄에 후처리된 한글 요약을 그대로 붙여 보여준다
allure-results/*.json → qa-report.html
BAT run_tests_and_report.bat

pytest부터 두 리포트까지 cmd.exe로 한 번에 잇는다.

  • 순서: pytest → 후처리 → (allure 있으면) 공식 리포트 → QA 리포트
  • allure CLI가 없으면 공식 리포트 단계만 건너뛰고 나머지는 계속 진행한다
  • 끝나면 pause로 창이 바로 안 닫힌다
더블클릭 또는 .\run_tests_and_report.bat
SH run_tests_and_report.sh

같은 네 단계를 bash 문법으로 옮긴 것.

  • 순서·산출물은 .bat와 동일 — 셸만 다르다
  • set -e로 중간 실패 시 이후 단계를 건너뛴다 (pytest 실패는 예외적으로 무시하고 계속 진행)
bash run_tests_and_report.sh
03 · .bat vs .sh

.bat와 .sh, 뭐가 다른가

만들어내는 결과는 같다. 다른 건 그 결과를 만드는 셸의 문법뿐이다.

항목run_tests_and_report.batrun_tests_and_report.sh
셸 cmd.exe (Windows 내장) bash (Git Bash · WSL · Mac · Linux)
PowerShell에서 실행 .\run_tests_and_report.bat bash run_tests_and_report.sh (Git Bash/WSL 필요)
폴더 삭제 rmdir /s /q allure-report rm -rf allure-report
CLI 존재 확인 where allure command -v allure
실패 시 동작 %errorlevel%을 직접 검사 set -e — 실패한 줄에서 중단(단, pytest 뒤엔 || true로 열어둠)
종료 후 pause로 창 유지 곧바로 닫힘

PyCharm 터미널의 기본 셸은 PowerShell이고, PowerShell은 .bat는 바로 실행하지만 .sh는 그 자체로 실행하지 못한다 — bash를 앞에 붙여야 하는 이유다.

04 · Commands

직접 실행하기

PyCharm 터미널(PowerShell) 기준. 순서를 지켜야 한다 — 후처리는 반드시 allure generate보다 먼저 끝나 있어야 한다.

공식 Allure 리포트

5단계 · 서버로 서빙
>_ Windows PowerShell −  □  ×
1PS automation> pytest -v --alluredir=allure-results
2PS automation> python tools/postprocess_allure_results.py allure-results
3PS automation> Remove-Item -Recurse -Force allure-report -ErrorAction SilentlyContinue
4PS automation> allure generate allure-results --output allure-report
5PS automation> allure open allure-report
1테스트 실행 — allure-results/에 원본 JSON이 쌓인다
2라벨 정리 — feature/testClass/testMethod 분리 + 한글 요약 추가
3이전 리포트 폴더 정리 — 재생성 전 지워둔다
4HTML 빌드 — allure-report/index.html 생성
5로컬 서버로 서빙 — 기본 브라우저가 자동으로 뜬다 (더블클릭으로 열면 정상 표시 안 됨)

QA 커스텀 리포트

3단계 · 파일 하나
>_ Windows PowerShell −  □  ×
1PS automation> pytest -v --alluredir=allure-results
2PS automation> python tools/postprocess_allure_results.py allure-results
3PS automation> python tools/generate_qa_report.py allure-results -o qa-report.html
1테스트 실행 — 공식 리포트와 같은 결과를 그대로 쓴다
2라벨 정리 — 두 리포트가 이 산출물을 공유한다
3qa-report.html 생성 — 더블클릭으로 바로 열람 (서버 불필요)

매번 위 줄들을 손으로 치는 대신, .\run_tests_and_report.bat (또는 bash run_tests_and_report.sh) 하나로 두 리포트를 순서대로 이어서 만들 수 있다 — 공식 리포트가 먼저 만들어지고, 그 다음 QA 리포트가 얹히는 순서는 그대로다.
