# 로그인 테스트 노트

`test_login.py`에 짠 두 테스트 — **로그인 실패**와 **로그인 성공(+세션 갱신)** — 가 각 줄에서 뭘 하는지, 그리고 왜 이렇게 짰는지 정리했습니다.

## 왜 실패 → 성공 순서인가

같은 파일 안에서 **위에 정의된 함수가 먼저 실행**되는 pytest 기본 동작을 그대로 이용했습니다. 두 순서를 이렇게 둔 이유는 기능적 의존성 때문이 아니라 **운영상 이유**입니다.

| | 계정 | 사람 개입 | 실행 시간 |
|---|---|---|---|
| **1. 로그인 실패** (TC-103) | testyoona (권한 없음) | 없음 — 완전 자동 | 수 초 |
| **2. 로그인 성공** (TC-114) | adminyoona (정상) | 필요 — 인증번호 직접 입력 | 사람이 반응할 때까지 대기 |

> **계정 두 개로 단순화**
>
> 원래는 권한별로 계정을 더 나누려 했는데(TC-134, 설치관리자 권한 케이스), 설치관리자 권한은 실제로 거의 안 쓰는 권한이라 지금 범위에서 뺐습니다. 지금은 **로그인 자체가 안 되는 계정(testyoona)**과 **정상 로그인 계정(adminyoona)** 둘로만 검증합니다.

> **그래서**
>
> 빠르고 완전 자동인 것부터 먼저 돌려서 **바로 결과를 확인**하고, 사람이 붙어있어야 하는 것(2번)은 뒤에 두는 게 자연스럽습니다. 순서를 바꿔도 테스트 자체는 깨지지 않습니다 — 둘은 서로 독립적입니다.

## 01. 로그인 실패 — 완전 자동

`test_TC103_login_fail_no_permission`

```python
def test_TC103_login_fail_no_permission(page):
    page.goto(STAFF_URL)
    page.get_by_placeholder("아이디").fill(NOAUTH_EMAIL)
    page.get_by_placeholder("비밀번호").fill(NOAUTH_PASSWORD)
    page.get_by_role("button", name="로그인").click()

    expect(page.get_by_text("권한이 없는 계정입니다")).to_be_visible()
```

- **`page.goto(STAFF_URL)`** — 로그인 화면으로 이동. `STAFF_URL`은 파일 위에서 `.env`의 `STAFF_URL`을 읽어옵니다.
- **`NOAUTH_EMAIL` / `NOAUTH_PASSWORD`** — 실제로 존재하는 계정(testyoona)입니다. 없는 계정이 아니라, 아이디·비밀번호는 맞는데 권한이 없어서 막히는 경우라 TC-102(존재 안 하는 계정)와는 다른 알럿 문구가 뜹니다.
- **`.click()`** — 로그인 버튼 클릭. `page` 기본 fixture라 **매 테스트마다 새 브라우저 컨텍스트**(로그인 안 된 깨끗한 상태)로 시작합니다.
- **`expect(...).to_be_visible()`** — THEN — "권한이 없는 계정입니다" 알럿이 뜨는지 확인. 이게 이 테스트의 **유일한 판정**입니다.

> **아직 손봐야 할 부분**
>
> `get_by_placeholder`, `get_by_text`의 문자열은 **추측으로 넣은 값**입니다. 실제 화면에서 Pick Locator로 정확한 값 확인 후 교체하세요.

## 02. 로그인 성공 — 반자동 (사람 개입 필요)

`test_TC114_login_success_and_refresh_session`

> **이건 "완전 자동화 테스트"가 아닙니다**
>
> 2단계 인증번호는 실제 문자로 오기 때문에 **코드가 알 수 없습니다.** 그래서 이 테스트는 아이디·비밀번호까지만 자동으로 하고, **그 다음은 사람이 뜬 브라우저 창에서 직접** 인증번호를 입력하고 [확인]을 누르는 구조입니다. 반드시 `--headed`로 실행해야 창이 보입니다.

```python
def test_TC114_login_success_and_refresh_session(page):
    page.goto(STAFF_URL)
    page.get_by_placeholder("아이디").fill(ADMIN_EMAIL)
    page.get_by_placeholder("비밀번호").fill(ADMIN_PASSWORD)
    page.get_by_role("button", name="로그인").click()

    # 여기까지 자동 — 2단계 인증 화면 진입 확인
    expect(page.get_by_text("인증번호")).to_be_visible()

    # ↓↓↓ 여기서부터 사람이 직접 ↓↓↓
    expect(page.get_by_role("button", name="로그인")).to_be_hidden(timeout=120_000)

    # THEN: 메인화면 진입 성공 → 세션 저장
    page.context.storage_state(path="auth.json")
```

- **`ADMIN_EMAIL` / `ADMIN_PASSWORD`** — 코드에 직접 안 적고 `.env`의 `STAFF_ADMIN_EMAIL` / `STAFF_ADMIN_PASSWORD`에서 읽습니다(adminyoona 계정). 비밀번호는 `.env`를 직접 열어서 채워 넣어야 동작합니다(대신 채울 수 없는 값입니다).
- **`expect("인증번호").to_be_visible()`** — 1단계 통과 후 2단계 화면으로 잘 넘어갔는지만 확인. 여기까진 완전 자동 구간.
- **`to_be_hidden(timeout=120_000)`** — 이게 "사람을 기다리는" 부분입니다. 로그인 버튼이 화면에서 사라질 때까지 **최대 2분** 계속 재확인합니다. 그 사이 사람이 인증번호를 입력하고 확인을 누르면, 화면이 메인으로 넘어가는 순간 이 줄이 통과되고 코드가 이어서 실행됩니다.
- **`storage_state(path="auth.json")`** — 지금 이 브라우저 세션(로그인 쿠키 등)을 파일로 저장합니다. 다음부터 다른 기능 테스트들이 이 파일을 불러오면 로그인 없이 바로 시작할 수 있습니다.

### 왜 메인화면 확인을 특정 메뉴 대신 "로그인 버튼 사라짐"으로 했나

계정마다 보이는 메뉴 구성이 다를 수 있어서, 특정 메뉴 이름에 의존하는 대신 **어떤 계정으로 로그인하든 항상 참인 조건**인 "로그인 화면을 벗어났다(로그인 버튼이 사라졌다)"를 기준으로 잡았습니다. 계정 권한 구조가 아직 다 확정된 게 아니라서(설치관리자 권한처럼), 가장 안전하고 일반적인 조건으로 시작한 것입니다.

> **더 정확하게 하고 싶다면**
>
> 실제 메인화면에서만 보이는 요소(예: 상단 계정명, 특정 GNB 로고 등)를 Pick Locator로 찾아 `to_be_hidden` 대신 `expect(메인화면_요소).to_be_visible(timeout=120_000)`로 바꾸면 더 명확한 판정이 됩니다. 지금 버전은 "확실히 안전한" 기준으로 시작한 것입니다.

## 돌리기 전에 확인할 것

1. **`.env`에 비밀번호 2개 채우기** — `STAFF_ADMIN_PASSWORD=`(adminyoona)와 `STAFF_NOAUTH_PASSWORD=`(testyoona) 뒤에 각 계정 비밀번호를 직접 입력하세요. 이 파일은 `.gitignore`에 있어 git에는 안 올라갑니다.
2. **TODO로 표시된 셀렉터 확인** — 두 테스트 모두 `get_by_placeholder`·`get_by_text`에 쓴 문자열이 추측값입니다. 실제 화면에서 Pick Locator로 정확한 값을 확인해서 바꾸세요.
3. **반드시 `--headed`로 실행**
   ```bash
   pytest test_login.py --headed -s
   ```
   `-s`는 print 등 출력이 안 가려지게 하는 옵션이라, 두 번째 테스트에서 사람이 개입할 타이밍을 놓치지 않는 데 도움이 됩니다.
4. **두 번째 테스트 실행 중엔 자리를 지키기** — 테스트가 2단계 인증 화면에서 멈춰 있는 동안, 뜬 브라우저 창에서 **직접 인증번호를 입력하고 [확인]을 눌러주세요.** 그러면 자동으로 이어서 진행되고 `auth.json`이 갱신됩니다.
