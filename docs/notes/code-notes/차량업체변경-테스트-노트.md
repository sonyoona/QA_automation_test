# 차량 업체 변경(이관) 테스트 노트

`test_vehicle_company_transfer.py`에 짠 TC-057, 058이 뭘 하는지 정리했습니다.

## TC-051/052와 뭐가 다른가

같은 "차량관리>차량관리(수정)" 모달을 다루지만, 검증하는 주장이 다릅니다.

| | TC-051/052 | TC-057/058 |
|---|---|---|
| 확인하는 것 | 모달을 그냥 열었을 때 파트너·리셀러 항목이 **존재하는지**(정적) | **업체(인수받을 업체)를 바꿨을 때** 파트너·리셀러가 어떻게 반응하는지(동적) |
| 기획서 근거 | STAFF 업체관리-업체/지점 목록 개선 | STAFF **리셀러 조건에 따른 파트너 및 업체 변경 제한 정책** (다른 기획서) |

TC-057 원문의 "◦예시: 모티스 주식회사 선택 시, 파트너 LG U+출력"이라는 문구가 힌트입니다 — "선택 시"라는 동작(업체를 실제로 바꾸는 액션)이 핵심이라, 그냥 모달을 여는 TC-051/052로는 커버되지 않습니다. TC-059 이후(이관 조건 충족/불충족)가 이 "업체 바꾸면 파트너는 전환되고 리셀러는 유지된다"는 전제 위에서 이어지므로, 미리 확인해둘 가치가 있다고 판단해 자동화했습니다.

## 왜 새 파일로 분리했나

TC-057~066은 TC 문서에서 `(업체변경)`이라는 별도 카테고리로 나뉘어 있고, 앞으로 10개 TC(이관 가능/불가 조건 등)가 이어지는 별개 클러스터입니다. `test_vehicle_edit_reseller.py`(필드 노출·자동전환)와 주제가 달라서, 파일이 커지는 걸 막으려고 분리했습니다. 다만 완전히 같은 모달을 다루기 때문에, 모달 진입·필드 찾기 헬퍼는 새로 만들지 않고 그대로 가져다 씁니다. 업체→파트너 매핑(`COMPANY_PARTNERS`)도 마찬가지로 `test_vehicle_register_reseller.py`에서 가져다 씁니다.

## 겪은 문제 — "업체" 라벨이 목록 필터 영역과 겹침

`_get_edit_field`로 "업체" 필드를 찾으려니 strict mode 에러가 났습니다.

```
resolved to 2 elements:
1) <div name="업체" ...>  (목록 화면 상단 필터의 "업체" 드롭다운)
2) <div name="업체" ...>  (지금 연 모달 안의 "업체" 필드)
```

모달은 기존 화면 위에 **겹쳐서** 뜨는 구조라, 뒤에 깔린 목록 화면의 "업체" 필터(라벨이 똑같이 "업체")가 DOM에서 사라지지 않고 그대로 남아있던 것입니다. "파트너 선택"/"리셀러 선택"은 목록 필터에 없는 문구(필터는 그냥 "파트너"/"리셀러")라 우연히 안 걸렸던 것뿐이고, `_get_edit_field` 자체는 원래 모달 범위로 안 좁혀져 있던 잠재 버그였습니다.

**해결**: `test_vehicle_edit_reseller.py`의 `_get_edit_field`를 아예 모달 범위로 좁히도록 고쳤습니다 (이 파일에서 새로 만들지 않고, 원본 헬퍼 자체를 더 안전하게 고쳐서 TC-051~056까지 다 같이 혜택을 보게 함).

```python
def _get_modal(page):
    """지금 열려있는 차량 수정 모달(section) 자체를 가리키는 Locator."""
    return page.locator("section").filter(has=page.locator('input[name="carNumber"]'))


def _get_edit_field(page, label_text):
    label = _get_modal(page).locator("label.form-label").filter(has_text=re.compile(f"^{re.escape(label_text)}$"))
    return label.locator("xpath=./following-sibling::*[1]")
```

`input[name="carNumber"]`는 모달 안에만 있는 요소라, 이걸 가진 `<section>`을 찾으면 정확히 지금 열린 모달만 골라낼 수 있습니다.

## 실제로 확인한 동작

054용1111(IMS모빌리티, 파트너 커넥트, 리셀러 커넥트)로 조사해봤습니다.

| 상태 | 업체(인수 대상) | 파트너 | 리셀러 | 리셀러 비활성 여부 |
|---|---|---|---|---|
| 모달 진입 직후 | 선택 안 됨("선택") | 커넥트 (차량의 현재 값) | 커넥트 (차량의 현재 값) | 비활성 |
| 업체를 "LG업체입니다"로 변경 | LG업체입니다 | **LG U+로 전환**(비활성 유지) | **커넥트 그대로**(안 바뀜) | **활성화됨** |

파트너는 새로 선택한 업체 기준으로 바로 전환되지만, 리셀러는 "값"은 그대로 유지한 채 "활성/비활성 상태"만 바뀝니다(TC-054~056에서 봤던 파트너별 활성화 규칙이 여기서도 그대로 적용되는 것) — 이 조합이 TC-057(파트너 전환)과 TC-058(리셀러 값 유지)이 각각 확인하는 지점입니다.

## TC-057 / TC-058

```python
from test_vehicle_register_reseller import COMPANY_PARTNERS


def test_TC057_vehicle_transfer_partner_updates_to_selected_company(logged_in_page):
    page = logged_in_page
    _open_carmgmt_edit_modal(page, CAR_PARTNER_CONNECT)

    transfer_company = "LG업체입니다"
    _select_transfer_company(page, transfer_company)

    partner_field = _get_edit_field(page, "파트너 선택")
    partner_text = partner_field.locator(".text").first
    expect(partner_text).to_have_text(COMPANY_PARTNERS[transfer_company])
    expect(partner_field).to_have_attribute("aria-disabled", "true")


def test_TC058_vehicle_transfer_reseller_unchanged(logged_in_page):
    page = logged_in_page
    _open_carmgmt_edit_modal(page, CAR_PARTNER_CONNECT)

    # 이 차량의 리셀러가 정확히 뭔지는 몰라도 된다 — 지금 실제 표시된 값을 그대로
    # "변경 전 기준값"으로 읽어서, 업체를 바꿔도 그 값이 유지되는지만 확인한다.
    reseller_field = _get_edit_field(page, "리셀러 선택")
    reseller_text = reseller_field.locator(".text").first
    expect(reseller_text).not_to_have_text("-")
    original_reseller = reseller_text.inner_text()

    _select_transfer_company(page, "LG업체입니다")

    expect(reseller_text).to_have_text(original_reseller)   # 업체를 바꿔도 안 바뀜
```

TC-058은 "안 바뀌어야 한다"를 검증하는 TC라, **변경 전 값도 먼저 확보**해뒀습니다 — 안 그러면 "원래도 저 값이었는지" vs "우연히 저 값으로 유지된 건지" 구분이 안 됩니다.

**"LG U+"를 `COMPANY_PARTNERS`로 가져온 이유 / 리셀러는 안 그런 이유**: TC-057의 파트너 값은 `COMPANY_PARTNERS[transfer_company]`로 가져오는 게 맞습니다 — `COMPANY_PARTNERS`가 정확히 "업체→파트너" 매핑이고, 파트너는 업체가 정해지면 하나로 고정되는 값이기 때문입니다.

TC-058은 처음에 리셀러 값도 `COMPANY_PARTNERS["IMS모빌리티"]`로 가져오려고 했었는데, **이건 잘못된 사용이었습니다.** `COMPANY_PARTNERS`는 "파트너"를 담은 딕셔너리지 "리셀러"를 담은 게 아닙니다. 054용1111의 경우 파트너=커넥트일 때 리셀러도 우연히 "커넥트"로 같아서 통과했을 뿐이고, 만약 파트너가 LG U+인 차량으로 이 TC를 확장했다면 리셀러가 [커넥트/LG U+] 둘 중 뭐가 될지 이 딕셔너리로는 알 수 없어서 바로 깨졌을 코드였습니다.

그래서 **애초에 리셀러 값이 뭔지 미리 알아야 할 필요 자체가 없다는 걸 깨닫고**, 지금 화면에 실제로 표시된 값을 `.inner_text()`로 그대로 읽어와 "변경 전 기준값"으로 삼는 방식으로 바꿨습니다. TC-058이 실제로 주장하는 건 "리셀러가 **어떤 값이든** 안 바뀐다"는 것이라, 그 값 자체를 외부에서 알아올 필요가 없었던 것입니다. 읽기 전에 `not_to_have_text("-")`로 값이 실제로 로딩됐는지부터 확인해서, placeholder를 "원래 값"으로 잘못 캡처하는 것도 막았습니다.

둘 다 저장(`[수정]` 버튼)까지는 안 가고 필드 값만 확인하는 **읽기 전용 TC**라, 데이터 변경 위험이 없습니다.
